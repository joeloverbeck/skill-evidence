```markdown
## Agent Brief

**Category:** enhancement
**Summary:** Add an optional `CronExpression` schedule to the public `SkillConfig` contract

**Current behavior:**
The public `SkillConfig` contract does not provide the required optional schedule behavior. A skill configuration therefore cannot opt into a schedule while retaining the established configuration-validation and serialization contracts.

**Desired behavior:**
`SkillConfig` should accept an optional `schedule` field whose value is a `CronExpression`. A valid configured schedule should be available through the public interface. When the field is absent, configuration behavior must remain unchanged and serialization must omit the field rather than emitting a placeholder value. An invalid schedule expression must be rejected through the existing configuration-validation error contract.

**Key interfaces:**
- `SkillConfig` — add an optional public `schedule` field with `CronExpression` as its value type
- `CronExpression` — the value contract used when reading and representing a configured schedule
- Configuration parsing and validation — accept valid schedule expressions and route invalid expressions through the existing configuration-validation error contract
- `SkillConfig` serialization — omit `schedule` when it is absent

**Acceptance criteria:**
- [ ] A configuration containing a valid schedule expression is accepted and exposes that value as a `CronExpression` through `SkillConfig.schedule`
- [ ] A configuration with no `schedule` field has the same accepted behavior and resulting configuration semantics as before this enhancement
- [ ] An invalid schedule expression is rejected with the existing configuration-validation error contract, without introducing a new error category for this field
- [ ] Serializing a `SkillConfig` whose schedule is absent omits the `schedule` field rather than emitting `null`, an empty value, or a default schedule
- [ ] Existing configuration behavior unrelated to scheduling remains unchanged

**Out of scope:**
- Defining or changing the accepted expression language of `CronExpression`
- Adding a required or default schedule when the field is absent
- Changing the existing configuration-validation error contract
- Creating or changing ADRs, schemas, installed package material, or other exact artifacts
```
