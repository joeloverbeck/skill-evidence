> ## Agent Brief
>
> **Category:** enhancement
> **Summary:** Add an optional cron schedule to the public `SkillConfig` configuration contract
>
> **Current behavior:**
> `SkillConfig` has no public schedule field, so a skill configuration cannot declare a cron schedule through this interface.
>
> **Desired behavior:**
> `SkillConfig` should accept an optional `schedule` field whose type is `CronExpression`. A valid schedule should be accepted as part of the configuration. Omitting the field must preserve existing configuration behavior. An invalid cron expression must produce the existing configuration-validation error, and serialization must omit the field when it is absent.
>
> **Key interfaces:**
> - `SkillConfig` — add the optional `schedule` field to its public configuration shape
> - `CronExpression` — use this type as the schedule field's value and apply its validity contract when configuration is read
> - The existing configuration-validation error — preserve this error contract for invalid schedule expressions
> - `SkillConfig` serialization — include a present schedule and omit the field entirely when it is absent
>
> **Acceptance criteria:**
> - [ ] The public `SkillConfig` interface accepts an optional `schedule` field of type `CronExpression`
> - [ ] A configuration containing a valid schedule is accepted and exposes that schedule through `SkillConfig`
> - [ ] A configuration with no schedule behaves as it did before this enhancement
> - [ ] An invalid schedule expression returns the existing configuration-validation error
> - [ ] Serializing a `SkillConfig` with a schedule includes the schedule field
> - [ ] Serializing a `SkillConfig` without a schedule omits the schedule field rather than emitting an absent or null value
>
> **Out of scope:**
> - Defining or changing runtime behavior that consumes a configured schedule
> - Changing the cron-expression contract or the existing configuration-validation error contract
> - Changes to unrelated configuration fields or interfaces
> - Requiring changes to any particular source file, test file, ADR, schema document, or package reference
