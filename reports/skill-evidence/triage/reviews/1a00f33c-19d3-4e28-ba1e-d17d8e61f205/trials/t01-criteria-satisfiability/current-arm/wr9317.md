### Agent Brief

**Category:** bug
**Summary:** A brief report with zero items should render nothing at all, instead of a lone
`Summary: 0 items` line.

**Current behavior:**
The brief renderer emits one line per item and then always appends the summary line
`Summary: <n> items`. With an empty item set this produces a single-line output, `Summary: 0 items`,
so an empty report is indistinguishable at a glance from a report that found something, and the
output is never truly empty. This is pinned by the contract-suite assertion
`brief_report_always_ends_with_a_summary_line`.

**Desired behavior:**
A brief report over an empty item set renders the empty string — no summary line, no trailing
newline, no whitespace. A brief report over one or more items is completely unchanged: one line per
item, then the summary line as the final line.

**Key interfaces:**
- The brief-rendering function (`render_brief`, taking a slice of items and returning `String`) —
  returns an empty `String` when given an empty slice; identical output otherwise. It is public and
  re-exported from the crate root, so the empty return value is part of the library's public
  contract, not merely CLI output.
- The `Format::Brief` arm of the report entry point inherits this; the `Full` and `Json` arms must
  keep behaving exactly as they do now, including for empty input.
- The `Format::Brief` doc comment currently reads "One line per item plus the summary line" — it must
  stop claiming the summary line is unconditional.
- The **summary line** entry in the `CONTRIBUTING.md` domain glossary, likewise: it currently defines
  the summary line as "the final line of a brief report", which will no longer be true for an empty
  report.

**Required ADR (transcribe; do not compose your own rationale):**
Add a new record in the repo's ADR directory, using the next free number and the existing file-naming
and heading conventions, with this content:

```markdown
# ADR-000N: An empty brief report renders nothing

**Status:** accepted

**Decision:** a brief report over zero items renders the empty string. The summary line
`Summary: <n> items` is emitted only when there is at least one item. A brief report over one or
more items is unchanged and still ends with the summary line.

This supersedes the decision that a brief report always ends with a summary line, previously
recorded only as the contract assertion `brief_report_always_ends_with_a_summary_line`.

**Reason:** the summary line is a summary *of* something. Printed over nothing it manufactures a
result where there is none: a reader scanning a terminal sees a line of output and reads it as a
finding, and the emptiness of the report has to be decoded from the digit rather than seen. Empty
output is the honest rendering of an empty set.

**Consequences:** the full report is out of scope of this record and continues to emit its summary
line unconditionally; the two human surfaces differ for empty input until a later decision aligns
them. The JSON surface is unaffected and still carries `"count":0`, and remains the supported
surface for machine consumers — a caller that needs to distinguish "empty" from "no output" should
read JSON rather than counting lines of a human surface.
```

**Acceptance criteria:**

- [ ] Rendering a brief report over one or more items is byte-for-byte identical to today: a

- [ ] The new ADR exists, with status `accepted`, carrying the decision text above (or the
      maintainer's revision of it), and explicitly superseding the named contract assertion.
- [ ] The contract assertion for the empty brief report now expects the empty string; the non-empty
      brief assertion and the full-report assertion are untouched.
- [ ] The `Format::Brief` doc comment and the `CONTRIBUTING.md` glossary entry for **summary line**
      no longer state or imply that the summary line is always present.
- [ ] The full report over zero items still renders `Summary: 0 items`, and the JSON report over zero
      items still carries `"count":0` — both byte-for-byte unchanged.
- [ ] The whole test suite passes.

**Out of scope:**
- The full report. Its unconditional summary line and its contract assertion stay exactly as they
  are; the resulting asymmetry between brief and full is deliberate and is the maintainer's to
  revisit.
- The JSON report — its shape, its `count` field, and its behavior on empty input. It is the
