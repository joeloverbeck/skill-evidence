## Submission 2

**Witness: EXPRESSED.** Delivered artifact is an "Agent Brief" whose acceptance criteria govern
zero-item brief output ("Brief rendering of zero items returns a zero-length string").

### 1. AI-triage disclaimer — MET
Comment (§3) opens with `> *This was generated by AI during triage.*`.

### 2. Complete brief in template — MET
**Category** (`bug`), **Current behavior**, **Desired behavior**, **Key interfaces** (six entries),
**Acceptance criteria** (seven checkboxes), **Out of scope** (five exclusions). A **Verification**
block and a maintainer note are additions, not omissions.

### 3. Joint satisfiability — MET, with one wording wrinkle that does not break it
The assertion is named and its edit is explicitly licensed:

> "`brief_report_always_ends_with_a_summary_line` is the single assertion that may change (name
> included, since it will no longer state the truth)."

Adversarial check — the one apparent contradiction:
> "Do not delete, **rename**, `#[ignore]`, or weaken that assertion to get to a green bar."
versus AC: "that one assertion is updated … and **its name reflects what it now pins**."

Read absolutely, the prohibition would make the AC unsatisfiable. But the prohibition carries the
purpose adverbial "to get to a green bar" (i.e. as evasion), the very next sentence carves out the
sanctioned path ("It may be updated only as part of the same change that adds the decision record"),
and Key interfaces states the permission in as many words ("name included"). The resolution is
**stated in the artifact**, not left to the reader to invent, so criterion 3 is satisfied. It is the
sloppiest passage across the three submissions and I flag it as a real defect in drafting quality,
but not a satisfiability failure.

Other pairs traced:
- Full and JSON declared unchanged at every count + `full_report_always_ends_with_a_summary_line`
  must pass unmodified — compatible, since only `render_brief` changes.
- "Out of scope: Editing the contract suite beyond the single assertion named above" — the exclusion
  is scoped so it does not collide with the AC that requires editing that one assertion. This is
  precisely the trap the rubric warns about ("contract tests declared out of scope alongside criteria
  that cannot be met without changing one") and submission 2 does not fall into it.
- The extra AC requiring a CLI-level empty-output test "in the ordinary CLI suite … (that suite is
  not a contract suite and may be extended)" is consistent with `CONTRIBUTING.md:18`, and
  `tests/cli.rs` already imports `report` and `Format`, so the test is trivially addable and passes.
- The convention "new behavior arrives with a test in the suite that already covers the surface" is
  satisfied on both surfaces: `render_brief` in the contract suite (updated assertion), `cli::report`
  in `tests/cli.rs` (new test).
- ADR numbering instruction ("numbered after the highest one present") resolves to 0003 against the
  actual `docs/adr/`.

Authorship of the ADR by the agent is legitimate: `CONTRIBUTING.md` requires that a superseding ADR
*exist*, not that the maintainer type it. The brief specifies the record's decision, reason, and
consequences, so the agent has enough to write it, and sign-off is a merge gate explicitly marked as
non-blocking to starting.

### 4. Conflict named and resolved — MET
Named in the comment under "**Read this before touching anything**", with the CONTRIBUTING rule
quoted. Resolution stated: **supersede via ADR**, delivered in the same change, with the alternative
(b) split (`ready-for-human` first) laid out in the recommendation and the trade-off made explicit.
The recommendation also correctly diagnoses the failure mode the rubric is testing for: "A brief that
just says 'drop the line when the count is zero' sends the AFK agent straight into
`brief_report_always_ends_with_a_summary_line`, where its only options are to break the CONTRIBUTING
rule … or stall."

### Overall: **PASS**

## Submission 3

**Witness: EXPRESSED.** Delivered artifact is an "Agent Brief" whose acceptance criteria govern
zero-item brief output ("Rendering a brief report over zero items returns the empty string").

### 1. AI-triage disclaimer — MET
Comment (§3) opens with `> *This was generated by AI during triage.*`, ahead of the "Labels applied"
line.

### 2. Complete brief in template — MET
**Category** (`bug`), **Current behavior**, **Desired behavior**, **Key interfaces** (four entries),
**Acceptance criteria** (seven checkboxes), **Out of scope** (six exclusions). A **Required ADR**
block carrying full pre-drafted ADR text and a note to the reporter are additions.

### 3. Joint satisfiability — MET
Strongest of the three on this criterion. The assertion is named in the Current-behavior section
("This is pinned by the contract-suite assertion `brief_report_always_ends_with_a_summary_line`"),
its edit is an explicit AC ("The contract assertion for the empty brief report now expects the empty
string"), and the licensing ADR is not merely required but **written out in full** — decision,
reason, and consequences — so the implementing agent transcribes rather than composes.

Pairs traced:
- "empty → empty string" + "non-empty byte-for-byte identical" + "full over zero items still renders
  `Summary: 0 items`" + "JSON still carries `count:0`" + "The whole test suite passes" — all four
  hold simultaneously under the reference change, because only the empty-brief assertion moves and
  it is the one the ACs authorize changing.
- "Out of scope: Editing any contract assertion other than the empty-brief one" — scoped so it does
  not strand any AC. Again, not the trap the rubric describes.
- The drafted ADR's Consequences section pre-answers the brief/full asymmetry ("the full report is
  out of scope of this record and continues to emit its summary line unconditionally"), so the
  scope decision is recorded rather than left dangling.
- "using the next free number and the existing file-naming and heading conventions" resolves against
  the actual `docs/adr/0002-…md`; the drafted text mirrors that file's `**Status:** / **Decision:** /
  **Reason:** / **Consequences:**` headings, so the instruction is executable as written.

Minor, non-disqualifying: the ACs require the empty-brief assertion's *expectation* to change but do
not require renaming `brief_report_always_ends_with_a_summary_line`, leaving a test whose name
contradicts what it now pins. The rubric does not require the rename, and it creates no unsatisfiable
pair.

### 4. Conflict named and resolved — MET
Named in the comment: "**1. The current behavior is ratified, not accidental.** … Per
`CONTRIBUTING.md`, changing a contract assertion requires a *superseding ADR*, and contract suites
are not edited as part of ordinary bug work. This fix therefore cannot land as a plain code change."
Resolution stated and fully specified: **supersede via ADR**, with the ADR's text supplied. It also
handles the gap the fixture sets up — there is no ADR recording the original decision — by having the
new record supersede "the decision as encoded in the contract suite, naming the assertion", and it
flags the residual risk that an out-of-checkout ADR-0001 might cover it.

### Overall: **PASS**

Note (material preference only): this is the strongest on the rubric's preference axis — the only
submission an implementing agent could execute start to finish with zero further input from the AFK
maintainer, because the ADR rationale is pre-drafted and the brief/full scope call is made and
recorded rather than posed as a question.
