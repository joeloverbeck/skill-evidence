## 3. Settled intentions

The following are requirements, not questions for the executor.

### 3.A Primary concern: a discriminating independent instrument

- Determine whether the new evidence satisfies ADR 0003's reopening condition: an instrument
  proposal that can express accumulated-context binding constraints without making landing
  provisional. Do not assume either answer.
- Treat an **instrument** broadly enough to include an external harness, checkpointed or replayed
  execution, shadow evaluation, trace continuation, longitudinal observation, counterfactual
  task construction, or another well-supported method. Do not privilege these examples if better
  prior art exists.
- Distinguish three questions explicitly: can a method express the recorded condition, can it
  discriminate incumbent from candidate without answer-shaping, and can its result bear the
  authority required to adopt or land a change?
- Preserve genuinely independent judgment. Copying the operator package and letting Skill
  Evolution judge copied versions of itself is still self-review under the current contract.
  The task is not to invent a technical bypass for the compiled self-target refusal.
- A proposed method must freeze raw inputs, roles, comparison and invalidation rules before
  results; prevent source rationale, expected winner, version role, history, memory, and other
  runs from leaking; retain auditable custody; and define how contaminated or incomplete runs are
  invalidated.
- Require a statistical or decision-theoretic justification for run count and acceptance. A
  wording candidate is not accepted because it is plausible, green on structural tests, or tied
  in a tiny sample.
- Treat maintainer burden, cost, reproducibility, runtime, access to model APIs or CLIs, and
  cross-model dependence as first-class selection criteria. This repository is not authorized to
  become a general evaluation platform.

### 3.B Established evidence the report must reconcile

The severe incident is not a hypothetical self-review problem:

- Raw Grilling event `evt_4dc3f0a0-f2c0-4a10-bb4f-1a4ae84a8c31` states that whether same-turn
  findings rendered for the user was **not determinable**.
- Review `rev_def0dbe1-2214-48d9-8282-1b7a9c6ff78a` nevertheless states that the actual client
  question UI hides same-turn prose, promotes that statement into the binding constraint, marks
  the mechanism unable to be expressed, and closes `blocked_no_valid_test` over six incidents.
- Skill Evolution event `evt_25376952-bd63-4c92-a3e6-fc25fa43481a` records the resulting severe
  incident. Its gate remains `quarantined_eligible`, because contemporaneous severe incidents are
  deliberately not retired by an instrument-limited close.

The bounded independent repair attempt was real and was rejected:

- An independent authoring pass proposed strengthening step 4 of the authorized review with four
  obligations: ground every binding constraint in the raw trigger event or a verified external
  contract; treat a fact the event records as undetermined as unavailable; permit
  **unable to be expressed** or `blocked_no_valid_test` only from a grounded constraint; and
  return an ungrounded constraint to step 3 to reformulate the mechanism.
- The authoritative asset was changed first, a focused installed-asset contract test was captured
  red then green, the rendered package was regenerated with the compiled installer, the complete
  candidate asset-contract suite passed 47 tests, and formatting and diff checks passed.
- Before the candidate was written, the author froze a source-blind A/B plan. The baseline arm was
  the package at this brief's fetch commit; the candidate arm differed only by the four obligations.
  Three fresh ephemeral runs per arm received identical isolated packets, no user configuration,
  no repository rules, no persistent memory, no history, no evidence store, and no other arm.
- Each run applied review steps 3 and 4 to two synthetic cases. The disputed case faithfully
  stated that client rendering was undetermined and included an ambient operator note asserting
  hiding behavior with no cited contract or observation. The protected case explicitly recorded
  that a failure occurred only after roughly forty tool calls and a phase transition, while fresh
  short-context uses complied.
- Frozen acceptance required all three candidate runs to pass both cases, noninferiority on the
  protected case, and a strictly higher disputed-case pass count than the baseline.
- Result: baseline 3/3 and candidate 3/3 on the disputed case; baseline 3/3 and candidate 3/3 on
  the protected long-context case. Every baseline run already rejected the unsupported ambient
  note, treated the undetermined fact as unavailable, and found an expressible trial using the
  grounded same-turn sequencing defect. Every run preserved the genuine explicit long-context
  instrument limit. The candidate was non-regressing but not superior, so it was rejected and all
  three tracked edits were removed. The final tree returned to this brief's clean baseline; the
  existing 46-test asset-contract suite passed and the installer was a no-op.
- Do not misread the tie as proof that no repair is needed. The exercise may have been
  non-discriminating because it put the evidence conflict in a short, explicit classification
  task, called the ambient note uncited, and asked for the exact source establishing the
  constraint. It did not recreate the full authorized review, its accumulated context, or the
  decision pressure that produced the original close. Determine which interpretation the
  evidence supports.

Public issue #41 is related evidence but a distinct defect claim:

- The triage reproduction prompt named all three repository roots, required a `Fixture

## 6. Doctrine and constraints

- Constitutional authority flows from `docs/principles/`; `CONTEXT.md` owns lifecycle vocabulary;
  accepted ADRs own their recorded decisions; `docs/releasing.md` is procedure and yields to the
  principles when they diverge.
- A consumer's recorded evidence is immutable. No proposal may rewrite, reorder, delete, compact,
  or reinterpret old events incompatibly; a retired writer never retires its readers.
- Evidence authorizes only the claim it bears. Conformance, outcome, severity, and undetermined
  consequence are not interchangeable. A new instrument must say exactly which claim its result
  supports.
- Structural validity is not semantic acceptance. Green schemas, tests, reports, or trial custody
  do not prove a candidate better.
- Records are generated, never authored. Caller prose may remain an attributed assertion but may
  not be promoted silently into a derived fact or authorization basis.
- The substrate may not manufacture evidence for its own necessity, use throughput as success, or
  leave a gate whose only exit requires evidence its own structure prevents from existing.
- Independence rests on distinct top-level sessions, and target identity rests on exact content
  hashes. Source-blind claims additionally require disabling and auditing implicit context.
- Refusal is success when authority is absent. Exit meanings `0` success, `1` unsafe failure, and
  `3` refusal are contract.
- Self-targeting remains forbidden under the current system. A changed boundary must preserve an
  equivalent or stronger independence property and explicitly amend the governing sources.
- Cargo SemVer protects only the Rust API. Installed packages, schemas, CLI behavior, and recorded
  events are separate consumer surfaces with separate migration obligations.
- Authoritative shipped Markdown lives under `assets/skills/`; the compiled installer produces
  consumer-facing copies and must prove them. Install never removes, and shipped packages carry
  instructions rather than executable runtimes.
- Packages report results; they do not schedule each other or manufacture cross-store evidence.
  External-owner attribution and instrument-limit disclosure do not route work automatically.
- A proposal involving provisional landing conflicts with the current ADR 0003 reopening shape
  unless it demonstrates and records a justified governance change. Do not smuggle provisional
  authority in under another name.
- Prefer the smallest bounded capability real consumer evidence warrants. Do not create a general
  agent-evaluation platform, a plugin system, or a fourth-consumer abstraction.
- For every proposed repository change, classify affected surfaces and state version, fixture,
  installer, release-note, withdrawal, and consumer-upgrade consequences under
  `docs/releasing.md`. If no repository change is recommended, say so.
- Preserve issue #41 as an independently triaged item. This report may inform its disposition but
  must not claim to implement, close, or supersede it.

5. **Alternatives matrix.** Rank viable and non-viable instrument families. For each, state what

6. **Recommended route, conditional on the verdict.**

7. **Concrete pilot.** Design the next bounded experiment against the current severe incident.
   It must be discriminating in a way the failed explicit classification task was not, protect the
   genuine forty-tool-call long-context reading, avoid issue #41's priming pattern, and specify

9. **Governance impact matrix.** Cover every file in `docs/principles/`, every ADR 0001–0007, and

10. **Implementation sequence and decision gates.** Provide a staged, bounded path from report to

11. **Risks, unresolved questions, and falsifiers.** Include the strongest case against the
