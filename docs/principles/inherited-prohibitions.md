# Inherited Prohibitions

Status: accepted constitutional memory

Failure modes that agents working in this repository must not gradually normalize. Each is
either inherited from the reusable constitutional pattern with a referent that actually exists
here, or learned from this repository's own short history.

Clauses of the source pattern with no referent here — autonomous canon, content networks,
worldbuilding, presentation fidelity, downstream projection — are deliberately absent. Their
absence is a decision, not an oversight: a prohibition with nothing to prohibit dilutes the ones
that bite.

## Against breaking the people who depend on this

- No change that invalidates evidence a consumer has already recorded.
- No field made required, retyped, or value-narrowed within a published schema version.
- No reader retired because its writer was retired.
- No version bump treated as sufficient protection for the recorded-evidence surface; Cargo
  SemVer covers the Rust API and nothing else.
- No fixture corpus edited to make a change pass.
- No installed package retired or renamed without naming, in the release, the directories each
  consumer must delete by hand.
- No consumer's deadline authorizing a change that breaks the other consumers.
- No defect reported against a vendored fork treated as a defect here until it is reproduced
  against a published version.

## Against this repository inventing its own importance

- No generalization for a hypothetical fourth consumer, or any abstraction whose only pressure is
  predicted rather than observed.
- No lifecycle platform, plugin system, or general agent-skill framework built beyond the
  smallest slice that real consumer use has proved necessary.
- No open-issue count, backlog size, or closure history treated as progress or as an obligation
  to continue.
- No internal inconsistency escalated into work when no consumer's real use can reach it.
- No secondary objective inferred from the code displacing a consumer's actual bottleneck without
  recorded human reprioritization.
- No public ecosystem assumed before users exist; publication is distribution, not an audience.
- No deferred cross-cutting requirement inflated from a cheap compatibility choice into
  exhaustive implementation before a real consumer and an accepted scope exist.
- No nominally small change allowed to expand internally without a stated appetite on
  implementation effort, surface area, and the maintainer's own burden.

## Against the substrate corrupting itself

- No event rewritten, reordered, compacted, or removed after it is appended.
- No structural validity treated as semantic acceptance: not a passing schema, not a green suite,
  not a merged branch, not a closed issue, not an agent-authored report.
- No severity ladder presented as proof of harm.
- No throughput count — reviews run, incidents captured, gates closed — presented as proof that
  the lifecycle is working.
- No evidence spent on a claim it does not bear; conformance evidence does not settle an outcome
  question, and the absence of an outcome deficit does not settle a conformance question.
- No gate left in a state whose only exit is evidence the gate's own structure prevents from
  existing.
- No architecture manufacturing evidence for its own necessity, fitness, or authority.
- No caller-supplied assertion silently promoted to a derived fact.
- No independence claim resting on anything weaker than distinct top-level sessions, and no target
  identity resting on anything weaker than a content hash.

## Against paperwork and prose infrastructure

- No hand-authored routing, provenance, status, or certification record where it can be generated.
- No feature requiring an operator to write prose into a record so the system can read it back as
  truth.
- No transient conversation as the only record of state, approval, pending work, or a return
  point.
- No prose-only return contract or hand-maintained routing graph between skill packages used as
  the interoperability layer; packages report results, they do not schedule each other.
- No shared mutable directory or universal schema mistaken for a durable substrate.

## Against unsafe acts on a consumer's files

- No side effect without narrow authority, a before-and-after state check, idempotency, and an
  inspectable receipt.
- No act that can half-apply and record nothing.
- No landing without the authorizing outcome that permits it.

## Against dishonest completion

- No technical success claimed while excluding the maintainer's own repeatable release,
  debugging, and upgrade burden across every consumer.
- No stored artifact — retained readers, frozen corpora, retired-workflow remnants — treated as a
  migration backlog merely because it shares the repository.
- No rejected, parked, or merely unadopted design left active in the tree or in default agent
  context; git history preserves the detail, and there is no duty to salvage it.
